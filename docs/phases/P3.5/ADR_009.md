# ADR-009 — Observation Contract Repair: Restore all five PA3 ragged feature families

**Status:** PROPOSED → implemented in P3.5
**Date:** 2026-10-22
**Phase:** P3.5 (prerequisite to P4)
**Supersedes:** nothing
**Relates to:** `PA4-P3-DESIGN-v1.0`, `PA4-P2-DESIGN-v1.0`, `ADR-008`, `PA4-P4-DESIGN-v1.0` §0.3/§4.2

---

## 1. Context

P4-0 preflight measured that PA4's served policy is **not** the full PA3 policy
input contract. PA3's encoder adds all five "ragged" feature families before the
encoder (`agent/model/ragged_embeddings.py`), and the pinned PA3 engine emits
them in every observation payload. PA4's Python plumbing decoded them with the
canonical PA3 `parse_batch()` and then **discarded them**, passing only the nine
fixed leaves to `ObservationBatch`. `ObservationBatch.__post_init__` then
silently substituted `RaggedBatch.empty(...)` for all five families.

Measured consequence (identical weights `20261006`, precision A, identical fixed
leaves, ragged toggled):

| Ragged rows/token | max\|Δtoken\| | relative | max\|Δglobal_repr\| | max\|ΔV\| |
|---|---|---|---|---|
| 1 | 4.679 | 1.894 | 4.533 | 0.0190 |
| 2 | 4.726 | 1.913 | 4.611 | 0.0202 |
| 3 | 4.768 | 1.930 | 4.411 | 0.0190 |

The encoder representation changes by ~190% purely from the missing families.
Every P3 decision was made blind to movesets, PP, types, status effects and
secondary move effects.

Real battles carry real content (9,616 seat-views, 8 envs, 600 steps):

| Family | max rows/seat-view | max rows/token | typically empty? |
|---|---|---|---|
| `effects` | 3 | 2 | sometimes |
| `repertoire` | 19 | 4 | sometimes |
| `types` | 23 | 2 | rarely |
| `base_moves` | 24 | 4 | never |
| `move_effects` | 45 | 3 | never |

Because `old_logprob` in P3 records was produced by the *reduced-input* policy,
G4-B's "real PA3-derived policy/value inputs verified including feature contract"
conjunct is unsatisfiable, and a reduced-input self-comparison would be exactly
the "call the same function twice" failure the P4 design forbids (§4.3).
The user rejected both a scoped PASS and a relaxed G4-B, and authorised a
bounded prerequisite repair instead of a P4 scope change.

## 2. Decision

Add all five ragged families to the PA4 observation contract on a **new,
separately versioned representation identity**, and make admission of old
nine-field-only records impossible.

### 2.1 Reuse the canonical PA3 decoder — do not reimplement

`pa3_engine.observation.parse_batch(fixed, ragged, count)` is already the
authoritative decoder and is **already called** by PA4 (`native_env.py:403`).
PA3 also supplies `split_batch_ragged_all`/`split_batch_ragged` and
`RaggedBatch.from_rows`/`.empty`/`.select`/`.narrow`/`.cat`. P3.5 reuses these
verbatim. The PA3 source is **read-only and unmodified**.

### 2.2 Transport representation

The frozen TensorDict (0.14.3) has **no `NestedTensor`**; `torch.nested` exists
but is opaque, unstable and not accepted by `TensorDict`. The transport therefore
uses an **explicit CSR-style encoding carried as ordinary dense tensors**, which
preserves lengths/counts/offsets/ordering/dtype/values exactly:

- `ragged.{family}_counts` — `int64 [B, 96]`, the authoritative per-token row count.
- `ragged.{family}_values` — `float32 [B, 96, cap_family, width_family]` padded.
- `ragged.{family}_lengths` — `int64 [B]` total rows actually present.
- `ragged.{family}_overflow` — `bool [B]`, set iff any token exceeded `cap_family`.

`cap_family` is a **padding capacity only**, never a semantic limit. Overflow
**fails closed** (raises), never truncates. Capacity is proven, not assumed:
measured maxima are ≤4 rows/token and the cap is set with a wide margin, and a
runtime assertion verifies `counts <= cap` on every decode. Padding rows are
always masked out by `counts` and can never reach the encoder.

### 2.3 Representation identity

New constant `OBSERVATION_REPRESENTATION = "pa4.observation.ragged.v2"`.
The **PA3 native contract hash is unchanged** (`dd723dc…`), because the native
payload format did not change — only how much of it PA4 forwards.

Records carrying only nine leaves (P3-era) are stamped
`pa4.observation.fixed9.v1` and are **refused** by the P4 ingest path with an
explicit `ObservationContractMismatch`, so they can never silently enter repaired
PPO training.

### 2.4 Per-seat semantics preserved

Ragged is decoded and stored **per seat**, from that seat's own
`observe_fixed_batch(handles, [side])` payload. No cross-seat bleed, no merging.
This matches the existing per-seat privacy contract.

## 3. Consequences

- G4-B becomes satisfiable on the true PA3 forward contract.
- P3 receipts are **historical evidence and are not rewritten**. P3's measured
  performance stands as a *reduced-input* baseline; P3.5 remeasures and reports
  the delta honestly.
- Wire/TensorDict payload grows (ragged ≈1.6 KB/seat-view native; padded
  transport larger). Actor-only throughput may regress; P3.5 measures and
  reports it rather than hiding it.
- Prior P3 transition records cannot be trained on. This is intended.

## 4. Alternatives rejected

| Alternative | Why rejected |
|---|---|
| Scoped P4 PASS on reduced input | User explicitly refused; would train on incomplete observations |
| Relax G4-B tolerance / self-comparison | Design §4.3 forbids; proves nothing |
| Introduce `NestedTensor` | Not available in frozen stack; would break `uv.lock` freeze |
| Cap/truncate ragged rows | Silent data loss; forbidden by P3.5 req. 5 |
| Modify PA3 source | Forbidden |
| Rewrite Rust engine | Out of scope; unnecessary — engine already emits everything |

## 5. Verification obligations (all must pass)

1. `parse_batch` payload → repaired PA4 observation → `ObservationBatch` equals
   PA3's canonical `ObservationBatch` field-by-field on real payloads.
2. Encoder/value outputs match PA3's canonical path to ≤1e-6 on identical
   weights and identical payloads, **with non-empty ragged**.
3. Negative controls: dropping/zeroing/corrupting any one family must produce a
   detectable mismatch and must be rejected, not silently accepted.
4. Round-trip: stored transition → reconstruct `RaggedBatch` → identical CSR
   `counts`/`values`/`host_counts` as the original.
5. Old nine-leaf records rejected by the new identity check.
6. P1/P2/P3 regressions green; `check_env_specs` green; real CUDA smoke green.
7. Actor-only throughput remeasured and reported against P3 baseline.
